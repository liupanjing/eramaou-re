# 城内互动接入说明

当前先接通一段普通城内事件，验证正文与流程分离：前往人物所在设施，在人物档案选择 **[7] 城内相处／相处记录**，选择话题，完成两轮回答，再统一结算。界面沿用正式游戏的日期栏、人物标题和菜单按钮。

这一步是小范围样本，不替代已有归顺交涉或旧训练系统，也尚未实现完整恋爱线。

## 可以试玩的内容

| 事件 | 当前状态 | 触发条件 |
| --- | --- | --- |
| 当值后的片刻 | 可玩，两轮各两个选项 | 成年、非亲属、在城部下，与魔王同处部下居所、兵营、工坊或市集 |
| 再续前话 | 待补正文 | 完成上一事件后出现；点击不结算 |

上午工作人员在开放的任职设施，空闲时段的成年部下按日程休息或前往兵营、工坊、市集。先在全城名册查看当前地点，再前往相同设施，点击在场人物进入档案。俘虏的归顺交流仍使用原来的 [1] 入口。角色移动规则见 [魔王城模块](魔王城模块.md)。

样本提供通用叙述，以及白梅花的专属回应变体。其他命名角色尚未补齐专属版本，通用叙述不算专属口上完成。普通人格与出身可以通过事件条件筛选，也可以用各人格的 profile 编号覆盖文本；本轮没有批量扩写这些内容。

## 文件与生成

- [castle_interactions.json](../content/castle_interactions.json)：可编辑的事件源文件。
- [build_interactions.py](../tools/build_interactions.py)：检查事件结构并生成原生表。
- [INTERACTION.ERB](../ERB/INTERACTION.ERB)：菜单、触发条件、统一结算和记忆。
- [INTERACTION_TEXT.ERB](../ERB/INTERACTION_TEXT.ERB)：生成结果，不直接编辑。

在项目根目录运行：

```powershell
python tools/build_interactions.py
python tools/check_castle.py
```

Emuera 运行时读取生成后的 ERB；它不会直接读取 JSON。修改后需要重新生成并重启游戏。这个文件独立于原来的 `character_voice_tasks.json`，后者的任务编号和草稿保持原样。

## 填写一个占位事件

以事件2为例：保持 `id` 和 `key`，按事件1的结构补齐 `text`，再将 `status` 从 `draft` 改成 `ready`。不要直接把空字符串当正文，也不要手动修改存档使它完成。

`text` 的字段如下：

| 字段 | 内容 |
| --- | --- |
| `opening` | 首次展开的正文，字符串列表，每项为一段 |
| `repeat` | 重谈开场；不可重谈的事件也保留完整结构 |
| `ending` | 完整选择、成功结算后的收尾 |
| `rounds` | 恰好两轮，每轮有 `prompt` 和2～3个 `choices` |
| 每个选项 | `label`、`reply`、`trust`、`affection` |

`trust` 使用既有信任值，单个选项允许 -10～10；`affection` 使用原好感原始值，10点相当于界面1％，单个选项允许 -100～100。二者独立计算，不修改归顺意向、归顺章节或原恋爱标识。原作超过100％的好感保留。

正文可用 `{name}`、`{master}`、`{self}`、`{address}`。称呼通过现有角色口吻接口替换，不要把“主人”等称呼写死。每项正文不含实际换行、双引号、反斜杠、百分号或其他格式指令；中文引号「」和全角百分号％可以使用。需要分段时增加列表项。

## 触发条件和记忆

| 字段 | 规则 |
| --- | --- |
| `id` | 1～15，唯一且永久保留；0槽保留。当前存储容量限于15种事件 |
| `key` | 唯一的英文标识 |
| `locations` | 允许的设施编号，不能为空；仍要求人物与魔王实际同处一地 |
| `profiles` | 可用角色／人格编号，空列表表示不限；编号来自既有角色口吻配置 |
| `temperaments` | 性格0～6，空列表不限 |
| `origins` | 出身1～6，空列表不限 |
| `min_trust` | 最低信任0～100 |
| `requires_event` | 前置事件ID；0表示无前置 |
| `requires_choice` | 前置事件最近一次的选择，如11、12、21、22；0表示不限选择 |
| `repeatable` | 完成后是否可在后续时段重谈 |
| `cost.actions` | 完整事件消耗1～3行动 |
| `cost.money` | 完整事件所需资金，0～100000 |

多个筛选条件同时满足才可用。所有事件还统一检查成年、非亲属、部下身份和当前在场状态；这些条件不能通过 JSON 放宽。

一次成功交谈保存完成次数、最近两轮选择和时段，记录跟随人物排序及原生存档；离城返回的旧字符串在末尾增加可选 `IX1` 字段，旧字符串仍可读取。相处记录目前只保留每个事件的最近选择，不是逐句回放或完整历史日志。

新互动与原日常交流共用“每人每时段一次”的认真交谈限制。重谈仍消耗行动与设定资金，但不重复增加信任或好感。归顺是身份，信任与好感是关系数值；本接口不会根据数值自动授予恋爱关系。

事件ID、选项顺序和选项含义在发布后必须保留，前置条件会读取存档中的旧选择编号。确需改变含义时，分配新事件ID并设计迁移；不要复用旧ID套入另一段故事。

## 专属文本

`variants` 按角色／人格 `profile` 编号指定 `overrides`。只覆盖文字，不另设数值效果；未覆盖字段沿用通用叙述。

| 覆盖键 | 对应位置 |
| --- | --- |
| `opening`、`repeat`、`ending` | 开场、重谈、收尾 |
| `r1`、`r2` | 第一轮／第二轮提示 |
| `r1c1_label`、`r1c1_reply` | 第一轮第一个选项及回应；其余按轮次与选项编号类推 |

每个覆盖值都是字符串列表，选项标题必须只有一项。覆盖一段文字会替换该字段的完整列表，不会拼接通用版尾句。专属版本需要保持选项含义一致。不同身份阶段的进一步细分与完整人物线留待后续逐段设计。

## 当前验证

原 Emuera 已验证人物档案入口、两轮选择、第二轮取消、缺稿退出、行动及资金不足、完整扣费、两种关系值独立变化、重谈、前置选择、人物排序、离城记忆和真实存档读回。

另在外部测试副本中把占位正文填为普通示例并设为 `ready`，重新生成后，事件能够完成并留下记录。正式源文件中的事件2仍为 `draft`。

运行验证不会复制或改写玩家存档。测试工具是 [prepare_interactions.py](../tools/prepare_interactions.py)，要求使用全新的项目外目录；其中的收费事件3只用于测试，不出现在正式游戏。
