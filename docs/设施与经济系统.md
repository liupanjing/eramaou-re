# 设施与经济系统

2026年10月18日，经营系统v1。使用原 Emuera 引擎，按中等经营深度实现。城堡现在有12处可前往的设施，人员、生产、研究、建设、交易、粮食供给及每日财政共用一套实际结算。

## 操作入口

- `201～212` 前往设施，每行显示四处，可点击按钮。
- 王座厅 `221` 建设、`224` 税政。
- 工坊 `223` 工艺排程、`224` 研究；原实验室和服装入口保留。
- 市集 `221` 批量买卖物资。
- 所有设施 `225` 当地经营、`226` 财务账本、`227` 城务与物资。
- 人员详情继续安排职责，新增加农场、采石场、魔晶井、市集和仓库物流岗位。

查阅与移动免费，交易、任命、开工、研究立项、亲自推进、税政调整和开停工各消耗1城务行动。取消、非法编号、资金或库存不足不扣行动与资源。查看报告后使用返回按钮，不会立即被主菜单刷新覆盖。

## 设施与岗位

| 设施 | 实际作用 |
| --- | --- |
| 王座厅 | 等级提高城堡基础收入，城务工作人员增加税务收入 |
| 地牢 | 现有容量与归顺管理保留，看守及驻防兵改善秩序 |
| 部下居所 | 提供居住容量；内务工作人员增加休息恢复 |
| 魔王寝宫 | 保留原会面入口及安置容量，不增加成人行为或正文 |
| 兵营 | 保留编制与召唤；教官积累整备度，最高降低20%军队维护，不增加兵力 |
| 家族居所 | 保留亲属管理及容量；成年照护人员额外改善家属恢复 |
| 工坊与研究室 | 分配实际工时给生产、研究；出勤人员还提供施工协助 |
| 农场 | 每日产粮，等级、工作人员和技术提高产量 |
| 采石场 | 生产建设、研究和工艺所需建材 |
| 魔晶井 | 生产研究与工艺所需魔晶 |
| 市集 | 买卖物资；等级改善价差和额度，工作人员增加商业收入 |
| 仓库 | 每类物资容量为150＋等级×150，物流技术另加150；工作人员降低粮耗 |

新五处设施初始为1级，提供起步生产和管理空间。旧七处设施等级保留。全部12处可排队升级，最高10级；原容量与兵营编制规则仍使用原设施等级。

岗位每处上限为设施等级加1，超编时按永久UID排序决定出勤，改变人物列表顺序不能抢占额外岗位。实际工时由学习、运动和话术能力决定，单人2～12。只有在城、未伤倒的成年部下或成年家属出勤；主角、俘虏、未成年者、出征或失联者不计入工作人员。

上午结束时记录一次出勤、配方、工坊模式及当时已有的项目。下午换岗位、开新项目不能倒领上午工时。工坊生产与研究模式使用出勤时的快照，选择新配方不会把旧工时挪给新配方。开停工则直接影响当晚是否运转；已经出勤的人员仍计工资。

## 物资循环

四种库存与旧 `ITEM` 分开保存，不把物资混入兵力总账：

| 物资 | 来源 | 用途 |
| --- | --- | --- |
| 粮食 | 农场或市集 | 在城人物和部队的日常供给 |
| 建材 | 采石场、工坊或市集 | 建设、研究、制作制品和炼晶 |
| 魔晶 | 魔晶井、工坊或市集 | 研究、亲自推进和工艺生产 |
| 制品 | 工坊或市集 | 在市集出售换取建设与运营资金 |

每个在城人物每日需1粮，每100名普通士兵向上取整再需1粮，军粮部分最高200，以兼容超大旧档兵团。物流工作人员最多减20%，物流技术另减10%，最终至少消耗1粮。

无人任职时，1级农场、采石场和魔晶井有少量自动产出，分别为7粮、2建材和1魔晶；有人出勤后进一步增加。农业技术提高25%，计算使用整数。库存满时停止增加，不删除旧档或其他情况下已有的超额库存；工坊成品放不下时不消耗该批原料。

工坊每批需要8工时，配方与成本见 `content/economy_rules.json`。可选择专注生产、专注研究或工时各半。原料不足时停在等待状态，不产生负库存；最多保留80工时。变更配方不会继承另一配方的储备工时。

## 建设和研究

全城有一条建设队列。升至下一级的费用为下一级等级平方×400资金，另需下一级等级×10建材，工期为下一级等级＋2。先支付、再逐日施工，完成后容量或效果才生效；已有工程时不能重复扣款开工。基础每日推进1，工坊实际出勤人员提供额外施工协助。

研究有一条队列，立项时支付资金、建材和魔晶。工坊按研究模式提供进度；魔王也可花1行动和2魔晶亲自增加5工时。暂时没有研究工时不丢失已付费用和进度，未完成前不能换项目重复立项。

| 技术 | 完成后的实际效果 |
| --- | --- |
| 农业与采掘改良 | 农场、采石场和魔晶井产量提高25% |
| 仓储与运输 | 每类库存容量增加150，粮食消耗减少10% |
| 精密工艺 | 工艺工时提高25%，每日交易额度增加50 |

目前项目不依赖尚未确定的主线、商路或忍者组织。三个项目是本版完整的技术范围，后续增加项目需要同时定义真实效果和存档字段，不能只有说明文字。

## 市集

输入物资编号后，数量正数表示购买、负数表示出售、0取消，每笔批量交易消耗1行动。每种物资买价始终高于卖价，升级市集只改善价差，不产生即时倒卖利润。

每日交易额度为50＋市集等级×25，精密工艺另加50；买卖都按数量占用额度，不能靠反复买卖重置。额度随实际日期改变，菜单刷新不重置。市集停工时不能交易。

本版是城堡物资市场，没有额外实现商路、运输队、随机商人或跨地区价格；报价清晰、没有消费战斗随机数的价格波动。

## 每日财政

`TAX_GET` 已改接新日结，原每月10、20、30日的旧税收不再重复发放。原税收正文与算法保留在 `TAX_LEGACY` 供追溯，实际日历不调用它。

每日收入来自城堡基础财政、王座厅等级、魔王等级、城务与市集出勤、现有领土攻略状态，再受威望、秩序和税政影响。原内政休息的 `FLAG:9` 作为当次收入加成使用，最高20%，结算后清零。

- 低税：收入80%，秩序每日＋2。
- 标准：收入100%，无额外税政秩序变化。
- 高税：收入125%，秩序每日－3。

每天支付设施维护、军队维护和实际出勤工资；每名出勤者工资12。兵营整备降低军队维护，军队维护的原始基数有3000上限，避免超大旧档无上限支出。停工设施仍支付一半维护，居所和仓库不通过停工消除基本成本。

首次启用的前三个日结免运营维护与工资，粮食仍消耗。资金不足时实际支付到余额，差额记入欠款；后续财政自动偿还欠款。不会为支付费用新增负现金，也不会因欠款自动删除角色或士兵。

缺粮会降低秩序并影响次日资源产出，欠款也会降低效率。二者存在时生产效率为75%，补给和还款后恢复。看守、驻防及内务可以改善秩序。没有新增处决、越狱或角色死亡惩罚。

## 账本与结算一致性

夜间通过原 `EVENT_NEXTDAY → TAX_GET` 结算一次。上午只记录出勤，不结算现金；保存、读档、查看界面和重复调用旧税收不会再发同日收入。不追补初始化前或跳过的历史日期。

保留最近28日账本：期初现金、城务收入、已付维护工资、市集、建设、研究、其他现金流、还款、期末现金、欠款与粮食缺口。另记城内生产消耗造成的四类物资净变化、需粮量、工艺批数与出勤人数。现金各项可以核对到实际余额；物资净变化不重复计入白天已完成的市场交易。

旧商店、战斗、原版事件等仍直接使用唯一的 `MONEY` 账户，其变化归入其他现金流，账本不把它们再发一遍。新支付同时维护旧 `EX_FLAG:4444` 记录。三项新交易分类均保存中途状态，读档不会丢失尚未结算的现金变化。

## 存档和边界

经济采用新的独立 `SAVEDATA` 数组，不改旧角色数据数组长度，不重置玩家资金、兵力、设施等级或人物。首次初始化赠予120粮、60建材、30魔晶，仅执行一次；不赠现金，不读取历史日期虚构累积产量。

旧居住区域仍是原七处，新增五处是可任职和前往的产业设施，不把农场或矿井自动设为人物住所。旧人物离返保存整个城务数组，新岗位也能随永久UID保留。

已有存档可继续读取，但新版存档包含新经济字段，不应再交给旧版执行文件加载后覆盖保存。测试均在项目外副本中进行，未改写玩家存档。

## 验证和维护

平衡数据源为 `content/economy_rules.json`，运行 `python tools/build_economy.py` 生成原生表；`--check` 验证生成结果。正式游戏无需 Python 或网络。

`tools/prepare_economy.py 全新项目外目录` 准备原引擎回归，覆盖出勤、资源买卖、真实菜单、建设研究、缺粮欠款、30日模拟与账本循环。测试副本生成94槽存档，可通过 `--load-save 副本/sav/save94.sav` 在另一个新目录验证读回。

原日期回归同时验证真实 `BEGIN TURNEND` 每完成一天只产生一笔经营日结，旧城堡交互回归同步适配建设队列。旧档测试通过 `check_castle.py --prepare 新目录 --load-save 旧档路径 --saved-scenario economy_legacy` 执行，输入档仅复制到副本。
